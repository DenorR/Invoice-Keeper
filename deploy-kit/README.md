# Invoice Keeper — руководство администратора сервера

Это руководство для тех, кто видит проект впервые. В нём всё, что нужно на сервере:
установка, настройка, резервные копии, перенос, обновление и удаление.
Каждое действие расписано по шагам и с готовыми командами.

В этой папке лежат:

| Файл | Что это |
|---|---|
| `invoice-keeper-1.6.0.run` | установщик: приложение и мастер настройки в одном файле |
| `invoice-keeper-1.6.0.run.sha256` | контрольная сумма установщика (проверять не обязательно, установщик проверяет себя сам) |
| `README.md` | это руководство |

> Если торопитесь, начните с раздела [Быстрый старт](#2-быстрый-старт). Если что-то пошло не так,
> смотрите [Решение проблем](#14-решение-проблем).

**Два способа развёртывания — результат одинаковый:**

| Способ | Когда | Инструкция |
|---|---|---|
| **Ansible** | инфраструктура описана кодом, один или много серверов, повторяемые раскатки | [`ansible/README.md`](../ansible/README.md) в репозитории |
| **Установщик `.run`** | один сервер, руками, за 5 минут | этот документ |

В обоих случаях **суперадмин (единственный администратор) задаётся только в `.env`**:
логин `ADMIN_LOGIN` и пароль `ADMIN_PASSWORD`. Через панель и API его не создать и не изменить.

## 1. Что это и как устроено

**Invoice Keeper** напоминает о регулярных платежах: аренде, серверах, подписках.
Части системы:

* **веб-панель:** что оплачено, что скоро и что просрочено, итоги по валютам RUB, USD и EUR;
* **REST API** `/api/v1` с документацией Swagger;
* **Telegram-бот:** заранее пишет в рабочий чат (по умолчанию за 3 дня до срока), в сообщении есть кнопка «✅ Оплачено».

Есть две роли:

* **администратор** заводит платежи и пользователей;
* **пользователь** отмечает оплаты.

Состав на сервере после установки:

```text
 браузер ──HTTPS 443──► Caddy ──► app ─┬─ веб-панель и API /api/v1
                     (сертификат       ├─ Telegram-бот ──► api.telegram.org
                      Let's Encrypt)   ├─ планировщик напоминаний (проверка раз в минуту)
                                       └─ база SQLite ── Docker-том invoice-keeper_ik-data

 systemd-таймер, каждую ночь ~03:00 ──► invoice-keeper backup --auto ──► /opt/invoice-keeper/backups
```

* Всё работает в Docker. Контейнеры:
  * `app`: приложение;
  * `caddy`: HTTPS и сертификат. В режиме без HTTPS его нет.
* Docker устанавливается автоматически, если его ещё нет.
* Данные хранятся в Docker-томе. Они переживают перезапуск, перезагрузку сервера и обновление.
* Настройки и секреты лежат в файле `/opt/invoice-keeper/.env`. Читать его может только root.
* Сервером управляет команда `invoice-keeper`, см. [раздел 7](#7-команда-invoice-keeper).

## 2. Быстрый старт

На своём компьютере откройте терминал в папке с установщиком и выполните:

```bash
scp invoice-keeper-1.6.0.run root@IP_СЕРВЕРА:
ssh root@IP_СЕРВЕРА
```

Дальше уже на сервере:

```bash
bash invoice-keeper-1.6.0.run
```

Мастер откроет `.env` — впишите логин и пароль суперадмина, сохраните. Затем ответьте ещё на 4 вопроса.
Через 1–3 минуты мастер покажет таблицу с адресом панели. Откройте адрес в браузере и войдите под суперадмином.

Подробности каждого шага описаны ниже.

## 3. Подготовка

### 3.1. Сервер

| Что | Требование |
|---|---|
| Система | Ubuntu 22.04 / 24.04 / 26.04 (проверено на 26.04), чистая или с другими сервисами. Debian 12 — если Docker с Compose уже установлен |
| Ресурсы | от 1 ядра, 1 ГБ памяти, 3 ГБ свободного места |
| Доступ | пользователь `root` по SSH (или пользователь с `sudo`) |
| Сеть | у сервера есть выход в интернет: нужен для Docker, сертификата и Telegram |
| Порты | для HTTPS свободны **80 и 443**. Для режима без HTTPS хватит одного любого порта |

Если у хостинга есть свой брандмауэр в панели управления («группы безопасности», «firewall»),
откройте в нём входящие **22, 80 и 443/TCP**. Брандмауэр `ufw` на самом сервере установщик настроит сам.

### 3.2. Что понадобится

* **IP-адрес сервера** и **пароль root** (или SSH-ключ). Их выдаёт хостинг.
* **Компьютер с `ssh` и `scp`.** В Windows 10/11, macOS и Linux они уже есть.
  В Windows подойдут PowerShell и «Командная строка».
* **Telegram-бот и группа.** Это необязательно: Telegram можно подключить и позже.

### 3.3. Telegram-бот и группа (5 минут)

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Придумайте боту имя и адрес. Адрес должен заканчиваться на `bot`, например `my_company_pay_bot`.
3. BotFather пришлёт **токен**, строку вида `1234567890:AAH…`. Скопируйте её: токен понадобится в мастере.
   Токен — это пароль от бота, никому его не показывайте.
4. Создайте группу для напоминаний или возьмите существующую рабочую. Добавьте туда бота.
   Чат мастер найдёт сам: на шаге 4 ему достаточно сообщения в этой группе.

> Один бот работает только на одном сервере. Если этот токен уже запущен где-то ещё,
> например на старом сервере или на компьютере разработчика, напоминания будут теряться.
> Для нового сервера заведите отдельного бота или остановите старый.

## 4. Установка по шагам

### 4.1. Скопировать установщик на сервер

Откройте терминал **на своём компьютере**, а не на сервере.

* Windows: «Пуск» → PowerShell.
* macOS и Linux: «Терминал».

Перейдите в папку с установщиком и скопируйте его на сервер:

```bash
cd путь/к/папке/deploy-kit
scp invoice-keeper-1.6.0.run root@IP_СЕРВЕРА:
```

* **Двоеточие в конце обязательно.** Оно значит «в домашнюю папку на сервере».
  Без двоеточия `scp` молча скопирует файл рядом же, на вашем компьютере, и напишет «1 file(s) copied».
* При первом подключении появится вопрос `Are you sure you want to continue connecting (yes/no)?`.
  Напечатайте `yes` и нажмите Enter.
* Пароль root при вводе не отображается, даже звёздочками. Это нормально.

Пример для Windows, если файл лежит в «Загрузках»:

```bash
cd $env:USERPROFILE\Downloads
scp invoice-keeper-1.6.0.run root@203.0.113.10:
```

### 4.2. Запустить установщик

```bash
ssh root@IP_СЕРВЕРА
bash invoice-keeper-1.6.0.run
```

Если вы вошли не под root, а под пользователем с `sudo`: `sudo bash invoice-keeper-1.6.0.run`.

Сначала установщик проверит систему: версию ОС, IP, память и свободные порты.
Затем при необходимости поставит Docker. После этого — 5 шагов: суперадмин в `.env` и 4 вопроса.

**Управление в мастере:**

| Действие | Клавиши |
|---|---|
| выбрать вариант | **↑ ↓**, затем **Enter** |
| ввести текст | напечатать, затем **Enter**. Подставленное значение можно стереть **Backspace** |
| принять значение по умолчанию | просто **Enter** |
| прервать установку | **Ctrl+C**. До подтверждения на шаге «Всё верно?» ничего не устанавливается, кроме Docker |

Если терминал показывает «кракозябры» или стрелки не работают, запустите мастер в простом
текстовом режиме: `bash invoice-keeper-1.6.0.run --plain`.

### 4.3. Вопросы мастера

**Шаг 1. Суперадмин — в `.env`**

Мастер не спрашивает логин и пароль администратора: суперадмин задаётся только в файле настроек.

1. Мастер создаст `/opt/invoice-keeper/.env` из шаблона и спросит «Открыть .env?» — нажмите Enter.
2. Откроется редактор nano, курсор уже на нужной строке. Впишите:

   ```text
   ADMIN_LOGIN=admin
   ADMIN_PASSWORD=ваш-пароль
   ```

   * логин — строчная латиница, цифры, точка, дефис, подчёркивание, от 3 до 64 символов;
   * пароль — не короче 8 символов. Если в нём есть `$`, `#` или пробел, возьмите его
     в одинарные кавычки: `ADMIN_PASSWORD='Pa$s #1'`.
3. Сохраните — **Ctrl+O**, затем **Enter**. Выйдите — **Ctrl+X**.

Мастер проверит значения. Если логин не подходит или пароль короче 8 символов, он предложит
открыть файл ещё раз. Остальные строки `.env` трогать не нужно: их мастер заполнит сам по ответам.

Можно подготовить `.env` заранее: создайте `/opt/invoice-keeper/.env` с этими двумя строками
до запуска установщика — тогда мастер сразу перейдёт к шагу 2.

**Шаг 2. Часовой пояс**

В этом поясе считаются сроки платежей, просрочка и время напоминаний. По умолчанию стоит пояс сервера.

| Город | Значение |
|---|---|
| Калининград | `Europe/Kaliningrad` |
| Москва, Санкт-Петербург | `Europe/Moscow` |
| Самара | `Europe/Samara` |
| Екатеринбург | `Asia/Yekaterinburg` |
| Омск | `Asia/Omsk` |
| Новосибирск | `Asia/Novosibirsk` |
| Красноярск | `Asia/Krasnoyarsk` |
| Иркутск | `Asia/Irkutsk` |
| Владивосток | `Asia/Vladivostok` |

Полный список выводит команда `timedatectl list-timezones`.

**Шаг 3. Адрес панели**

| Вариант | Адрес | Когда выбирать |
|---|---|---|
| **HTTPS · IP.sslip.io** (по умолчанию) | `https://203.0.113.10.sslip.io` | своего домена нет. Бесплатно, сертификат выдаётся автоматически |
| **HTTPS · свой домен** | `https://pay.example.ru` | домен есть, и его A-запись **уже** указывает на IP сервера |
| **HTTP** | `http://203.0.113.10` или `http://203.0.113.10:8081` | только для проверки или внутренней сети: без шифрования |

* `sslip.io` — общедоступный сервис: имя `203.0.113.10.sslip.io` всегда указывает на IP `203.0.113.10`.
  Ничего регистрировать не нужно.
* Для HTTPS на сервере должны быть свободны порты 80 и 443, и они должны быть открыты снаружи.
* В режиме HTTP мастер спросит порт, по умолчанию 80. Если порт 80 занят другим сайтом, укажите, например, 8081.

**Шаг 4. Telegram-бот**

1. Выберите «Подключить» и вставьте токен от BotFather. Вставка в терминал: **Ctrl+V**, **Ctrl+Shift+V** или правая кнопка мыши, в зависимости от программы.
   Токен на экране не отображается. Мастер проверит его у Telegram и покажет имя бота.
2. Мастер попросит написать **любое сообщение в группе с ботом**, например `/start`, и будет ждать до 2 минут.
   Добавить бота в группу во время ожидания тоже можно.
3. Дальше всё зависит от того, что нашёл мастер:
   * один чат — мастер выберет его сам;
   * несколько чатов — предложит выбрать нужный стрелками;
   * ничего — нажмите **Enter** и введите ID чата вручную. Бот присылает ID в ответ на команду `/chatid`.
4. В выбранный чат придёт пробное сообщение «✅ Invoice Keeper подключён к этому чату».

Можно выбрать «Пропустить» и подключить Telegram позже командой `invoice-keeper config`.
Без Telegram панель работает полностью, только напоминания не отправляются.

**Шаг 5. Демо-данные**

* **«Загрузить пример».** Будут созданы платежи для показа: аренда в RUB, сервер в USD,
  подписка в EUR с просрочкой и история оплат. Ещё появятся два пользователя, `user` и `accountant`.
  Мастер спросит их пароль: свой (один на обоих) или сгенерированный (сохранится в `.env`).
* **«Начать с пустой базы».** Только администратор, всё остальное вы заведёте сами.

Демо можно убрать позже: `invoice-keeper reset-demo --empty`.

**Подтверждение**

Мастер покажет таблицу с выбранными настройками. На «Всё верно, устанавливаем?» ответьте «Да».

### 4.4. Что происходит дальше

На экране видно каждый этап:

1. Файлы копируются в `/opt/invoice-keeper`.
2. Записываются настройки `.env` (доступ только у root).
3. Проверяются порты.
4. Открываются порты в `ufw`, если он включён.
5. Включаются ночные резервные копии.
6. Образ приложения собирается и запускается. Первый раз это занимает 1–3 минуты.
7. Мастер проверяет, что приложение отвечает и адрес открывается снаружи. В режиме HTTPS к этому моменту уже получен сертификат.

В конце появится таблица: адрес панели, Swagger, администратор, состояние Telegram,
где лежат копии и настройки. Ниже — основные команды управления.

**Пароли в итоговой таблице не показываются никогда.**

Повторный запуск установщика безопасен. Если установка прервалась (разрыв SSH, ошибка сети),
просто запустите тот же файл ещё раз.

## 5. Первый вход и пароли

1. Откройте в браузере адрес из итоговой таблицы, например `https://203.0.113.10.sslip.io`.
2. Введите логин и пароль администратора.

**Где посмотреть пароли.** Это нужно, если вы забыли пароль суперадмина или выбрали
«Сгенерировать» для демо-пользователей. Пароли хранятся только в `.env` на сервере:

```bash
grep -E '^(ADMIN_PASSWORD|DEMO_)' /opt/invoice-keeper/.env
```

| Строка | Чей пароль |
|---|---|
| `ADMIN_PASSWORD=` | администратора (`ADMIN_LOGIN`) |
| `DEMO_USER_PASSWORD=` | демо-пользователя `user` |
| `DEMO_ACCOUNTANT_PASSWORD=` | демо-пользователя `accountant` |

Пароли пользователей, которых администратор завёл в панели, в `.env` не хранятся.
В базе лежат только их хеши. Если пользователь забыл пароль, администратор задаёт новый в панели
([раздел 8](#8-администратор-и-пользователи)).

**Swagger.** Документация API открывается по адресу `https://ВАШ_АДРЕС/api/v1/docs`.
Как авторизоваться:

1. Выполните `POST /auth/login` и скопируйте `token` из ответа.
2. Нажмите **Authorize** и вставьте токен.

## 6. Работа в панели — коротко

| Задача | Где | Кто может |
|---|---|---|
| посмотреть, что оплатить сейчас и что просрочено | **Главная** | все |
| добавить регулярный платёж (название, сумма, валюта, ближайший срок, периодичность) | **Регулярные платежи → Добавить платёж** | администратор |
| изменить, прекратить или возобновить регулярный платёж | **Регулярные платежи** → «…» | администратор |
| выбрать несколько платежей: прекратить, возобновить, перенести в категорию | **Регулярные платежи** → галочки слева | администратор |
| завести категории («Офис», «Серверы»…) и работать с группой | **Регулярные платежи → Категории** | администратор |
| отметить оплату (дата не позже сегодняшней) | **Платежи** или **Главная** → «Оплачено» | все |
| исправить дату оплаты, прикрепить чек (ссылку или файл), написать комментарий, отменить отметку | **Платежи** → кружок-отметка → «Изменить» / «Отменить оплату» | все |
| сроки на месяц и бюджет | **Календарь** | все |
| добавить сотрудника, сменить ему пароль, удалить | **Пользователи** | администратор |
| кто что делал (входы, оплаты, чеки, изменения); открыть или удалить файл чека | **Журнал действий** → нажать на запись | администратор |
| окно напоминания, загрузка файлов чеков | **Настройки** | администратор |
| отметить оплату прямо из Telegram | кнопка «✅ Оплачено» под напоминанием | все в чате |

**Когда приходят напоминания:**

* за 3 дня до срока (по умолчанию; меняется в «Настройках», у платежа может быть свой срок), один раз на каждый период;
* если платёж добавлен, когда до срока меньше 3 дней, — сразу;
* по оплаченному периоду бот больше не пишет до окна следующего периода.

Правила расчёта периодов, просрочки и итогов описаны в основном `README.md` проекта.

## 7. Команда invoice-keeper

Все действия на сервере выполняются одной командой. Её нужно запускать под root.
Список команд выводит `invoice-keeper help`.

### Состояние

| Команда | Что делает |
|---|---|
| `invoice-keeper status` | показывает контейнеры и проверяет, что панель отвечает по своему адресу |
| `invoice-keeper info` | адрес, Swagger, версия, логин администратора, часовой пояс, бот и чат Telegram, где копии |
| `invoice-keeper logs` | журнал приложения в реальном времени, выход — **Ctrl+C** |
| `invoice-keeper logs caddy` | журнал HTTPS-сервера: сертификат, входящие запросы |
| `invoice-keeper version` | установленная версия |

### Работа

| Команда | Что делает |
|---|---|
| `invoice-keeper stop` | остановить приложение. Данные остаются, бот перестаёт отвечать |
| `invoice-keeper start` | запустить снова |
| `invoice-keeper restart` | перезапустить и **применить изменения из `.env`** |
| `invoice-keeper config` | мастер настройки с текущими значениями: пароль админа, адрес, Telegram, часовой пояс, демо |

### Резервные копии и перенос

| Команда | Что делает |
|---|---|
| `invoice-keeper backup` | сделать копию базы прямо сейчас |
| `invoice-keeper backups` | список копий (дата, тип, размер) и время следующей автоматической |
| `invoice-keeper restore ФАЙЛ` | восстановить базу из копии. Текущая база сначала сохраняется |
| `invoice-keeper restore latest` | восстановить самую свежую копию |
| `invoice-keeper export [ФАЙЛ]` | зашифрованный архив для переноса: база и настройки |
| `invoice-keeper import ФАЙЛ` | загрузить такой архив в эту установку |
| `invoice-keeper reset-demo` | пересоздать базу с демо-данными. Текущая база сначала сохраняется |
| `invoice-keeper reset-demo --empty` | пересоздать пустую базу и выключить демо-данные |

### Удаление

| Команда | Что делает |
|---|---|
| `invoice-keeper uninstall` | удалить контейнеры. Данные, копии и настройки остаются |
| `invoice-keeper uninstall --purge` | удалить всё: приложение, базу, копии, настройки, таймер и саму команду |

Команды, которые что-то заменяют или удаляют, сначала спрашивают подтверждение `[д/Н]`.
Чтобы согласиться, введите `д` (или `y`) и нажмите Enter. Просто Enter означает «нет».

## 8. Администратор и пользователи

### Администратор — один, только в `.env`

В системе **один администратор** — владелец. Он задаётся в файле `/opt/invoice-keeper/.env`.
Через панель и API его нельзя создать, изменить или удалить, и второго администратора тоже не завести.
Это защищает от захвата панели.

```text
ADMIN_LOGIN=admin
ADMIN_PASSWORD=пароль-администратора
```

**Сменить пароль или логин** — только в `.env`:

1. Откройте файл: `nano /opt/invoice-keeper/.env`.
2. Исправьте `ADMIN_PASSWORD` и/или `ADMIN_LOGIN`. Логин — строчная латиница, цифры, `.`, `-`, `_`,
   от 3 символов. Пароль — от 8 символов; если в нём есть `$`, `#` или пробел — в одинарных кавычках.
   Сохраните файл: **Ctrl+O**, затем **Enter**. Выйдите: **Ctrl+X**.
3. Примените изменения: `invoice-keeper restart`.

На серверах, которые разворачивает Ansible, `.env` генерируется из inventory: меняйте
`ik_admin_login` / `ik_admin_password` там (пароль — в Vault) и запускайте плейбук.

После перезапуска старый пароль (или логин) перестаёт работать, а все сессии администратора завершаются.
Смена логина переименовывает ту же учётную запись: созданные им платежи и записи журнала остаются за ним.

Логин администратора не может совпадать с логином обычного пользователя. Если совпадает, приложение
не запустится и скажет об этом в `invoice-keeper logs`.

> Версии 1.2–1.3 позволяли завести дополнительных администраторов строкой `ADMINS`.
> По требованию кейса администратор один: при обновлении строка `ADMINS` удаляется из `.env`
> (прежний файл сохраняется как `.env.bak-ДАТА`), а дополнительные администраторы теряют доступ.
> Сотрудникам, которым нужен доступ, заведите обычных пользователей.

### Пользователи — в панели

Обычных пользователей (бухгалтеров, сотрудников) администратор заводит в панели:

* **добавить:** **Пользователи → Добавить пользователя**. Нужны логин, имя и пароль не короче 6 символов;
* **сменить пароль или имя:** кнопка ✏️ «Изменить»;
* **удалить:** кнопка удаления. Сессии пользователя сразу завершаются, а его отметки об оплате сохраняются в истории.

Пользователь видит все платежи и может отмечать оплаты. Создавать и менять платежи
и пользователей он не может: сервер отвечает 403.

## 9. Изменение настроек и Telegram

### 9.1. Через мастер (рекомендуется)

```bash
invoice-keeper config
```

Мастер подставит текущие значения: на каждом шаге достаточно нажать Enter, чтобы оставить как было.
Через мастер можно изменить:

* часовой пояс;
* адрес (HTTPS, свой домен или HTTP);
* Telegram;
* демо-данные.

Прежний `.env` сохраняется рядом как `.env.bak-ДАТА`. Приложение перезапустится само.

### 9.2. Вручную в `.env`

```bash
nano /opt/invoice-keeper/.env      # исправить, сохранить: Ctrl+O, Enter, выйти: Ctrl+X
invoice-keeper restart             # применить
```

Все параметры перечислены в [справочнике](#163-настройки-env). Чаще всего меняют эти:

| Что нужно | Строка в `.env` |
|---|---|
| напоминать не за 3, а за 5 дней | в панели: «Настройки» → 5 дней (или `REMINDER_DAYS_BEFORE=5` как значение по умолчанию) |
| дольше не разлогинивать | `SESSION_TTL_HOURS=720` (30 дней) |
| Telegram доступен только через прокси | `TELEGRAM_PROXY=socks5://user:pass@host:1080` |
| сменить логин или пароль администратора | `ADMIN_LOGIN=…`, `ADMIN_PASSWORD=…` ([раздел 8](#8-администратор-и-пользователи)) |

Строки `PUBLIC_URL`, `DOMAIN`, `APP_PORT`, `COOKIE_SECURE`, `COMPOSE_FILE` и `COMPOSE_PROJECT_NAME`
заполняет установщик. Адрес меняйте через `invoice-keeper config`: мастер согласованно поправит все эти строки.

### 9.3. Telegram: подключить, сменить чат или бота, отключить

Все варианты есть в `invoice-keeper config`, на шаге 4:

* **«Оставить как есть»:** бот и чат не меняются;
* **«Настроить заново»:** новый токен и/или другой чат. Чат ищется так же, как при установке;
* **«Отключить напоминания»:** токен и чат удаляются из `.env`.

Пока мастер ищет чат, приложение остановлено. Иначе оно само заберёт сообщение из группы.
После мастера приложение запустится снова.

**Команды бота в чате:**

* `/upcoming` — что и когда оплатить в ближайшие 30 дней;
* `/chatid` — ID чата;
* `/help` — список команд.

Кнопка «✅ Оплачено» под напоминанием отмечает оплату сегодняшней датой. Кто нажал, записывается в журнал действий.

**Проверить бота:** `invoice-keeper info` покажет имя бота и чат.
Строка «бот (не отвечает)» значит, что токен неверный или у сервера нет доступа к Telegram,
см. [решение проблем](#14-решение-проблем).

## 10. Резервные копии

### 10.1. Что и когда копируется

* **Копируется база целиком.** В ней платежи, периоды, история оплат, пользователи, журнал действий
  и отметки об отправленных напоминаниях.
  Файл настроек `.env` в копии не входит. База и `.env` вместе попадают в архив переноса,
  см. [раздел 11](#11-перенос-на-другой-сервер).
* **Копия делается без остановки приложения.** Используется встроенный механизм SQLite.
  Каждая копия проверяется (`PRAGMA integrity_check`) и сжимается.
* **Копии хранятся в `/opt/invoice-keeper/backups`.** Папка закрыта для всех, кроме root.
  Имена файлов выглядят так: `daily-20261024-030512.db.gz`.

**Расписание:** каждую ночь около **03:00 по времени сервера**, со случайной задержкой до 15 минут.
По воскресеньям дополнительно сохраняется еженедельная копия.
Если в 03:00 сервер был выключен, копия будет сделана сразу после включения.
Если приложение остановлено, копия пропускается, и это записывается в журнал копий.

**Сколько хранится** (старые удаляются автоматически):

| Тип | Когда создаётся | Хранится |
|---|---|---|
| `daily` — ежедневная | каждую ночь | 7 последних (неделя) |
| `weekly` — еженедельная | по воскресеньям (ночь с субботы на воскресенье) | 4 последних (месяц) |
| `manual` — вручную | `invoice-keeper backup` | 20 последних |
| `before-update` | перед каждым обновлением | 5 последних |
| `before-restore` | перед восстановлением и `reset-demo` | 5 последних |
| `before-import` | перед загрузкой архива | 5 последних |

Одна копия демо-базы весит около 10 КБ. Даже большая база займёт единицы мегабайт.

### 10.2. Посмотреть копии и сделать копию вручную

```bash
invoice-keeper backups     # список копий и время следующей автоматической
invoice-keeper backup      # сделать копию сейчас, например перед важными изменениями
```

Пример вывода `invoice-keeper backups`:

```text
  Резервные копии · /opt/invoice-keeper/backups (доступ только у root)

  Дата              Тип                    Размер
  24.10.2026 20:00  перед обновлением      8.0K
  24.10.2026 03:07  ежедневная             8.0K
  23.10.2026 03:02  ежедневная             8.0K

  Автоматически: каждую ночь около 03:00 по времени сервера; хранятся 7 ежедневных и 4 еженедельных.
  Следующая автоматическая копия: Sun 2026-10-25 03:04:11
```

### 10.3. Восстановить базу из копии

```bash
invoice-keeper restore latest                                              # самая свежая копия
invoice-keeper restore /opt/invoice-keeper/backups/daily-20261023-030215.db.gz   # конкретная
```

Что делает команда:

1. Спрашивает подтверждение.
2. Сохраняет текущую базу как `before-restore-…`, чтобы восстановление можно было отменить.
3. Останавливает приложение, проверяет файл копии и подкладывает его.
4. Запускает приложение.

Если файл повреждён или это не база Invoice Keeper, восстановление отменяется, прежняя база остаётся на месте.

**Отменить неудачное восстановление:** восстановите копию `before-restore-…`, которую команда только что сделала:

```bash
invoice-keeper restore /opt/invoice-keeper/backups/before-restore-ДАТА.db.gz
```

Настройки `.env` при восстановлении не меняются: пароль администратора и Telegram останутся текущими.

### 10.4. Хранить копии вне сервера

Копии на самом сервере не спасут, если пропадёт сервер. Раз в неделю или перед рискованными
работами скачивайте **зашифрованный архив** к себе.

1. На сервере:

   ```bash
   invoice-keeper export      # придумайте пароль архива; файл появится в /root/
   ```

2. На своём компьютере:

   ```bash
   scp root@IP_СЕРВЕРА:/root/invoice-keeper-*.ikb .
   ```

Обычные копии `*.db.gz` **не зашифрованы**. Хранить их вне сервера можно только в надёжном месте.
Скачать их можно так:

```bash
scp root@IP_СЕРВЕРА:/opt/invoice-keeper/backups/daily-*.db.gz .
```

Чтобы восстановить такую копию со своего компьютера, загрузите её на сервер
(`scp файл.db.gz root@IP_СЕРВЕРА:`) и выполните `invoice-keeper restore /root/файл.db.gz`.

### 10.5. Расписание: проверить, запустить вручную, изменить

```bash
systemctl list-timers invoice-keeper-backup.timer    # когда следующий запуск
systemctl start invoice-keeper-backup.service        # выполнить ночную копию прямо сейчас
cat /var/log/invoice-keeper-backup.log               # журнал: «ок: …» или «ОШИБКА: …»
```

Чтобы сменить время, например на 01:30:

1. Откройте редактор переопределения:

   ```bash
   systemctl edit invoice-keeper-backup.timer
   ```

2. В открывшемся редакторе впишите:

   ```ini
   [Timer]
   OnCalendar=
   OnCalendar=*-*-* 01:30:00
   ```

3. Сохраните и закройте редактор, затем перезапустите таймер:

   ```bash
   systemctl restart invoice-keeper-backup.timer
   ```

Пустая строка `OnCalendar=` обязательна: она сбрасывает прежнее время.
Переопределение сохранится и после обновлений.

Выключить автоматические копии: `systemctl disable --now invoice-keeper-backup.timer`.
Следующее обновление включит их снова.

## 11. Перенос на другой сервер

Перенос делается одним зашифрованным архивом `.ikb`.

**Что переносится:**

* вся база: платежи, история оплат, пользователи с паролями, журнал действий,
  отметки об отправленных напоминаниях (поэтому повторных напоминаний не будет);
* настройки из `.env`: логин и пароль администратора, токен бота и чат, часовой пояс, параметры напоминаний.

**Что не переносится:**

* адрес: IP у нового сервера другой, его задают заново;
* старые резервные копии;
* журналы.

Архив зашифрован (GnuPG, AES-256) паролем, который вы придумываете при экспорте.
Пароль нигде не сохраняется: без него архив не открыть.

### 11.1. Пошагово

**На старом сервере:**

```bash
invoice-keeper export
```

Придумайте пароль архива, от 8 символов, и введите его дважды. Команда покажет путь к архиву,
например `/root/invoice-keeper-old-20261024-2010.ikb`, и готовые команды для следующих шагов.

Сразу после экспорта остановите старый сервер:

```bash
invoice-keeper stop
```

Так новые отметки об оплате не потеряются, а бот не будет работать в двух местах одновременно.

**На своём компьютере** скачайте архив и отправьте его вместе с установщиком на новый сервер:

```bash
scp root@СТАРЫЙ_IP:/root/invoice-keeper-old-20261024-2010.ikb .
scp invoice-keeper-old-20261024-2010.ikb invoice-keeper-1.6.0.run root@НОВЫЙ_IP:
```

**На новом сервере:**

```bash
ssh root@НОВЫЙ_IP
bash invoice-keeper-1.6.0.run --import invoice-keeper-old-20261024-2010.ikb
```

1. Установщик спросит пароль архива. Даётся 3 попытки.
2. Покажет, откуда архив: дату, старый сервер и прежний адрес.
3. Задаст только один вопрос — адрес панели (шаг 3).
4. Покажет таблицу для подтверждения.

Остальные настройки уже есть в архиве. Дальше установка идёт как обычно, а данные загружаются из архива.

**Проверьте новый сервер:**

1. Откройте панель по новому адресу и войдите **с прежним паролем**.
2. Проверьте, что платежи и история на месте.
3. Выполните `invoice-keeper info`: бот и чат должны отобразиться.

**После проверки:**

* удалите установку на старом сервере: `invoice-keeper uninstall --purge`;
* удалите файлы архива: `rm /root/*.ikb` на обоих серверах. На своём компьютере архив можно
  оставить как резервную копию в надёжном месте.

**Если был свой домен,** заранее, до установки на новом сервере, поменяйте A-запись домена на новый IP.
Иначе сертификат не выдадут. Проверить, что запись обновилась: `ping pay.example.ru` должен показать новый IP.

**Если был адрес `…sslip.io`,** новый адрес будет `НОВЫЙ_IP.sslip.io`. Сообщите его коллегам.

Версия на новом сервере должна быть **той же или новее**, чем на старом.
Более старую базу новая версия обновит сама.

### 11.2. Загрузить архив в уже работающую установку

Это нужно, например, чтобы откатиться к состоянию из архива или слить тестовый сервер с боевым.

```bash
invoice-keeper import /root/архив.ikb
```

* База и настройки заменяются данными из архива. Адрес этого сервера сохраняется.
* Текущая база перед этим сохраняется как `before-import-…`, прежний `.env` — как `.env.bak-ДАТА`.

### 11.3. Без вопросов (для скриптов)

Пароль архива можно передать переменной `IK_PASSPHRASE`.
Учтите, что так он попадёт в историю команд оболочки:

```bash
IK_PASSPHRASE='пароль-архива' invoice-keeper export /root/move.ikb
IK_PASSPHRASE='пароль-архива' ACCESS_MODE=https bash invoice-keeper-1.6.0.run --import move.ikb --yes
```

## 12. Журналы

| Что | Как посмотреть | Ротация |
|---|---|---|
| приложение: запуск, ошибки, Telegram, напоминания | `invoice-keeper logs` | Docker: 5 файлов по 10 МБ на контейнер |
| HTTPS (Caddy): сертификат, запросы | `invoice-keeper logs caddy` | так же |
| установка, обновления, перенастройка | `/var/log/invoice-keeper-install.log` | logrotate: раз в месяц, хранится 6 |
| ночные резервные копии | `/var/log/invoice-keeper-backup.log` | так же |
| действия людей: входы, оплаты, изменения | панель → **Журнал действий** (администратор) | хранится в базе |

Полезные варианты:

```bash
cd /opt/invoice-keeper
docker compose logs --tail=200 app                 # последние 200 строк без «живого» режима
docker compose logs --since 1h app                 # за последний час
docker compose logs app | grep -iE 'error|ошибк'   # только ошибки
tail -n 50 /var/log/invoice-keeper-install.log     # чем закончилась последняя установка
```

Команды `docker compose` выполняйте из папки `/opt/invoice-keeper`: состав сервисов записан в `.env`.
Пароли и токены в журналы не пишутся.

## 13. Обновление и удаление

### 13.1. Обновление

1. Скопируйте на сервер новый установщик:

   ```bash
   scp invoice-keeper-НОВАЯ_ВЕРСИЯ.run root@IP_СЕРВЕРА:
   ```

2. Запустите его на сервере:

   ```bash
   bash invoice-keeper-НОВАЯ_ВЕРСИЯ.run
   ```

Установщик сам поймёт, что приложение уже стоит, и спросит «Обновить до …?». Затем он:

1. делает копию базы `before-update-…`;
2. заменяет файлы приложения. `.env` и папка `backups` не трогаются;
3. дописывает в `.env` новые параметры, если они появились;
4. пересобирает и перезапускает приложение, проверяет, что оно отвечает.

Вопросы мастера при обновлении не задаются: все настройки сохраняются.
Простой длится около минуты.

Если нужно заодно поменять настройки, запустите `bash invoice-keeper-НОВАЯ_ВЕРСИЯ.run --reconfigure`.

**Откат на прошлую версию** (если после обновления что-то не так):

1. Запустите установщик прошлой версии: `bash invoice-keeper-СТАРАЯ_ВЕРСИЯ.run`.
2. Восстановите копию, сделанную перед обновлением:

   ```bash
   invoice-keeper restore /opt/invoice-keeper/backups/before-update-ДАТА.db.gz
   ```

### 13.2. Временно остановить

```bash
invoice-keeper stop      # данные, настройки и копии на месте
invoice-keeper start
```

`invoice-keeper uninstall` (без `--purge`) удаляет контейнеры, но оставляет данные, настройки и копии.
Повторный запуск установщика всё подхватит.

### 13.3. Полное удаление

Если данные могут понадобиться, сначала сделайте архив: `invoice-keeper export`.

```bash
invoice-keeper uninstall --purge
docker image rm invoice-keeper:latest caddy:2-alpine
rm -f /root/invoice-keeper-*.run /root/invoice-keeper-*.ikb /var/log/invoice-keeper-install.log*
```

* Первая команда спросит подтверждение (`д`) и удалит:
  * приложение, базу и Docker-тома;
  * резервные копии и `.env`;
  * таймер копий, настройки logrotate, журнал копий;
  * команду `invoice-keeper`.
* Вторая удалит образы Docker.
* Третья удалит установщики, архивы и журнал установки.

Docker и правила брандмауэра остаются: ими могут пользоваться другие сервисы.
Если они больше не нужны:

```bash
ufw delete allow 80/tcp && ufw delete allow 443/tcp
apt purge -y docker.io docker-compose-v2 docker-buildx
```

Правило для порта 22 (SSH) не удаляйте, иначе потеряете доступ к серверу.

## 14. Решение проблем

Сначала выполните три команды. Обычно их вывода достаточно, чтобы понять причину:

```bash
invoice-keeper status
invoice-keeper info
invoice-keeper logs        # Ctrl+C — выход
```

### Копирование и подключение

**`scp` написал «1 file(s) copied» и не спросил пароль.**
Пропущено двоеточие: `root@IP_СЕРВЕРА:`. Файл скопировался на вашем же компьютере.

**`Permission denied (publickey,password)`.**
Неверный пароль или пользователь. Проверьте, что подключаетесь как `root`, и пароль от хостинга.

**`Connection timed out` / `Connection refused`.**
Неверный IP, сервер выключен или порт 22 закрыт в панели хостинга.

**«Файл установщика повреждён: контрольная сумма не совпала».**
Файл скопировался не целиком. Скопируйте его ещё раз через `scp`.
Если нужно, сверьте сумму с файлом `.sha256`:

```bash
sha256sum invoice-keeper-1.6.0.run
```

### Установка

**«Порт 80 или 443 занят».** На сервере работает другой веб-сервер. Посмотреть, кто занял порт:

```bash
ss -ltnp | grep -E ':(80|443) '
```

Варианты:

* остановить его, например `systemctl disable --now nginx` или `apache2`;
* выбрать режим HTTP с другим портом: `invoice-keeper config` → шаг 3.

**Установка прервалась** (обрыв SSH, ошибка сети). Запустите тот же `.run` ещё раз, это безопасно.
Подробности ошибки:

```bash
tail -n 50 /var/log/invoice-keeper-install.log
```

**Docker не устанавливается: «Could not get lock /var/lib/dpkg/lock».**
Система сама ставит обновления. Подождите 5–10 минут и запустите установщик снова.

**В терминале «кракозябры», стрелки не работают.** Запустите в простом режиме: `bash invoice-keeper-1.6.0.run --plain`.

### Панель

**Панель не открывается по HTTPS.**

1. Сертификат выдаётся до минуты. Подождите и обновите страницу.
2. Посмотрите журнал Caddy: `invoice-keeper logs caddy`. Ошибки со словами `challenge` или `timeout`
   значат, что снаружи закрыты порты 80/443. Откройте их в панели хостинга ([3.1](#31-сервер)).
3. Для своего домена A-запись должна указывать на этот сервер: `ping ваш.домен`.

**«Приложение запущено, но адрес не отвечает».** Чаще всего это брандмауэр хостинга.
Проверьте, открывается ли панель с самого сервера: `curl -I http://127.0.0.1:ПОРТ` для режима HTTP.

**Забыли пароль администратора.**
Посмотрите его: `grep ^ADMIN_PASSWORD= /opt/invoice-keeper/.env`.
Или задайте новый: впишите его в `ADMIN_PASSWORD` (`nano /opt/invoice-keeper/.env`) и выполните `invoice-keeper restart`.

**Пользователь забыл пароль.** Администратор: панель → **Пользователи** → ✏️ → новый пароль.

**«Слишком много неудачных попыток входа».** После 10 неудачных попыток за 5 минут вход с этого IP
временно блокируется. Подождите 5 минут.

**Неправильное время или сроки сдвинуты на день.** Неверный часовой пояс. Исправьте: `invoice-keeper config` → шаг 2.

**Приложение не запускается после правки `.env`.** Причину покажет `invoice-keeper logs`.
Обычно это опечатка в строке или логин администратора совпал с логином пользователя. Прежний вариант файла часто лежит
в `/opt/invoice-keeper/.env.bak-*`.

### Telegram

**Бот молчит, напоминания не приходят.** Проверяйте по порядку:

1. `invoice-keeper info`: если нет бота или чата, выполните `invoice-keeper config` → шаг 4.
2. Бот добавлен в группу и его не удалили.
3. Ищите в журнале ошибки Telegram:

   ```bash
   cd /opt/invoice-keeper && docker compose logs app | grep -i telegram
   ```

4. `Conflict: terminated by other getUpdates request` значит, что этот же бот запущен где-то ещё:
   на старом сервере или у разработчика. Остановите его там или заведите нового бота.
5. Проверьте, доступен ли Telegram с сервера:

   ```bash
   curl -sS -m 10 https://api.telegram.org >/dev/null && echo ok
   ```

   Если ответа нет, укажите прокси в `.env` (`TELEGRAM_PROXY=…`) и выполните `invoice-keeper restart`.

**Почему не пришло напоминание по конкретному платежу.** Напоминание отправляется один раз на период,
когда до срока остаётся 3 дня или меньше. Оплаченные периоды и прекращённые платежи не напоминаются.
Если Telegram был недоступен, отправка повторится автоматически.

**Мастер не нашёл чат.** Сообщения бота, скорее всего, забирает другая копия приложения.
Нажмите Enter и введите ID вручную: напишите в группе `/chatid`, и работающий бот ответит числом.
Для групп число отрицательное, например `-1001234567890`.

### Резервные копии и перенос

**В журнале копий «пропуск: приложение остановлено».** Ночью приложение не работало.
Запустите его: `invoice-keeper start`.

**«ОШИБКА: копию сделать не удалось».**

1. Проверьте место на диске: `df -h /`.
2. Проверьте, что приложение работает: `invoice-keeper status`.
3. Попробуйте вручную: `invoice-keeper backup`.

**`restore`: «Файл повреждён или это не база Invoice Keeper».** Выберите другую копию из `invoice-keeper backups`.

**`import` / `--import`: «Неверный пароль архива».** Пароль чувствителен к регистру и раскладке.
Если пароль утерян, архив открыть невозможно. Сделайте новый `export` на старом сервере.

**«Здесь уже установлен Invoice Keeper» при `--import`.** На сервере уже есть установка.
Загрузите архив в неё: `invoice-keeper import ФАЙЛ`.

### Место на диске

```bash
df -h /                                   # сколько свободно
du -sh /opt/invoice-keeper/backups        # сколько занимают копии
docker image prune -f                     # удалить старые неиспользуемые образы после обновлений
```

## 15. Безопасность

**Что уже сделано установщиком:**

* **Секреты хранятся только в `/opt/invoice-keeper/.env`** с правами `600`: читать файл может только root.
  Там лежат пароль администратора, пароли демо-пользователей и токен бота.
  Пароли не выводятся на экран и не пишутся в журналы.
* **Копии закрыты для всех, кроме root:** папка `backups` с правами `700`, файлы копий — `600`.
* **Архивы переноса зашифрованы** (AES-256). Пароль архива нигде не хранится.
* **Пароли пользователей** хранятся в базе в виде хешей scrypt с солью.
  Сессии хранятся как хеши токенов. Перебор паролей ограничен.
* **Соединение с панелью** идёт по HTTPS: сертификат Let's Encrypt, HSTS, защищённые cookie.
  Защита от SQL-инъекций, XSS и CSRF описана в основном `README.md`.
* **Брандмауэр.** Если `ufw` включён, открыты только 22 и 80/443 (или выбранный порт).
  Само приложение наружу не смотрит: в режиме HTTPS к нему можно попасть только через Caddy.

**Что стоит сделать вам:**

1. **Выбирайте HTTPS.** Режим HTTP передаёт пароли открытым текстом. Он годится только для проверки.
2. **Придумывайте для архивов длинный пароль**, например из 4–5 слов. Храните архивы вне сервера в надёжном месте.
3. **Регулярно обновляйте систему:** `apt update && apt upgrade -y`.
4. **Входите на сервер по SSH-ключу, а не по паролю.**

   1. На своём компьютере создайте ключ и отправьте его на сервер:

      ```bash
      ssh-keygen -t ed25519
      ssh-copy-id root@IP_СЕРВЕРА
      ```

      В Windows вместо `ssh-copy-id` добавьте содержимое `%USERPROFILE%\.ssh\id_ed25519.pub`
      в файл `/root/.ssh/authorized_keys` на сервере.
   2. Проверьте, что `ssh root@IP_СЕРВЕРА` пускает без пароля.
   3. Только после этого отключите вход по паролю.
      В `/etc/ssh/sshd_config` поставьте `PasswordAuthentication no`, затем выполните `systemctl restart ssh`.
      Не закрывайте текущую сессию, пока не проверите вход в новом окне.

5. **Не отправляйте `.env` в чаты и почту.** Токен бота, если он утёк, можно заменить:
   @BotFather → `/revoke` → новый токен → `invoice-keeper config` → шаг 4.

## 16. Справочник

### 16.1. Где что лежит

| Путь | Что там |
|---|---|
| `/opt/invoice-keeper/` | файлы приложения. При обновлении заменяются целиком, кроме `.env` и `backups/` |
| `/opt/invoice-keeper/.env` | все настройки и секреты (права `600`) |
| `/opt/invoice-keeper/.env.bak-ДАТА` | прежние версии `.env` после `config` и `import` |
| `/opt/invoice-keeper/backups/` | резервные копии базы (права `700`) |
| `/opt/invoice-keeper/VERSION` | установленная версия |
| `/opt/invoice-keeper/installer/` | команда `invoice-keeper`, мастер `setup.sh`, функции копирования |
| Docker-том `invoice-keeper_ik-data` | сама база: `/app/data/invoice-keeper.db` внутри контейнера |
| Docker-тома `invoice-keeper_caddy-*` | HTTPS-сертификаты |
| `/usr/local/bin/invoice-keeper` | ссылка на команду управления |
| `/etc/systemd/system/invoice-keeper-backup.timer` и `.service` | расписание ночных копий |
| `/etc/logrotate.d/invoice-keeper` | ротация журналов установки и копий |
| `/var/log/invoice-keeper-install.log` | журнал установки и обновлений |
| `/var/log/invoice-keeper-backup.log` | журнал ночных копий |

### 16.2. Порты

| Режим | Порты снаружи | Что слушает |
|---|---|---|
| HTTPS (sslip.io или свой домен) | 80, 443 | Caddy: 80 нужен для выдачи сертификата и перенаправления на 443 |
| HTTP | выбранный порт (по умолчанию 80) | приложение |
| всегда | 22 | SSH, не относится к приложению |

### 16.3. Настройки `.env`

После правки выполните `invoice-keeper restart`.

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `ADMIN_LOGIN` | `admin` | логин администратора (он в системе один) |
| `ADMIN_PASSWORD` | вписывается при установке | его пароль, от 8 символов. С `$`, `#` или пробелом — в одинарных кавычках |
| `APP_TIMEZONE` | пояс сервера | пояс для сроков и напоминаний (IANA, `Europe/Moscow`) |
| `TELEGRAM_BOT_TOKEN` | пусто | токен бота. Пусто — напоминания выключены |
| `TELEGRAM_CHAT_ID` | пусто | ID чата для напоминаний (бот покажет по `/chatid`) |
| `TELEGRAM_PROXY` | пусто | прокси для Telegram: `http://…` или `socks5://…` |
| `TELEGRAM_API_URL` | пусто | свой адрес Bot API (если используется локальный сервер Bot API) |
| `TELEGRAM_POLLING` | `true` | `false` — только отправлять, не принимать команды и кнопки |
| `REMINDER_DAYS_BEFORE` | `3` | за сколько дней напоминать по умолчанию (от 3 до 365; в панели можно изменить) |
| `REMINDER_CHECK_INTERVAL_SECONDS` | `60` | как часто проверять сроки |
| `SESSION_TTL_HOURS` | `168` | сколько часов действует вход (7 дней) |
| `SEED_DEMO_DATA` | `true` | загружать демо-данные в **пустую** базу при запуске |
| `DEMO_USER_PASSWORD` | генерируется | пароль демо-пользователя `user` (применяется, когда демо загружается) |
| `DEMO_ACCOUNTANT_PASSWORD` | генерируется | пароль демо-пользователя `accountant` |
| `LOG_LEVEL` | `INFO` | подробность журнала: `DEBUG`, `INFO`, `WARNING` |

Эти параметры заполняет установщик. Меняйте их через `invoice-keeper config`, а не вручную:

| Параметр | Назначение |
|---|---|
| `PUBLIC_URL` | адрес панели. Используется в кнопке «Открыть в панели» в сообщениях бота |
| `DOMAIN` | домен для HTTPS-сертификата (`IP.sslip.io` или свой) |
| `APP_PORT` | порт панели в режиме HTTP |
| `COOKIE_SECURE` | `true` при HTTPS |
| `COMPOSE_FILE` | набор файлов Docker Compose: с HTTPS или без, с IPv6 или без |
| `COMPOSE_PROJECT_NAME` | имя проекта Docker (`invoice-keeper`) |

### 16.4. Параметры установщика

```bash
bash invoice-keeper-1.6.0.run [параметры]
```

| Параметр | Что делает |
|---|---|
| без параметров | установка с мастером. Если приложение уже стоит — обновление |
| `--yes` | без вопросов: значения берутся из переменных окружения (таблица ниже), остальное — по умолчанию |
| `--reconfigure` | пройти мастер заново, даже если приложение уже установлено (обновление + новые настройки) |
| `--import АРХИВ` | установка с переносом базы и настроек из архива `invoice-keeper export` |
| `--plain` | без анимации и стрелок: вопросы обычным текстом |
| `--extract ПАПКА` | только распаковать содержимое, ничего не устанавливая |
| `--version` | версия установщика |
| `--help` | справка |

**Без вопросов (`--yes`)** установщик берёт всё из `/opt/invoice-keeper/.env`, а чего там нет — из
переменных окружения или значений по умолчанию. Суперадмин обязателен: если его нет, установщик
создаст `.env` из шаблона, попросит вписать `ADMIN_LOGIN` и `ADMIN_PASSWORD` и остановится.

| Переменная | По умолчанию | Значение |
|---|---|---|

| `APP_TIMEZONE` | пояс сервера | часовой пояс |
| `ACCESS_MODE` | `https` | `https` — IP.sslip.io, `domain` — свой домен (нужен `DOMAIN`), `http` — без шифрования |
| `DOMAIN` | — | домен для `ACCESS_MODE=domain` |
| `APP_PORT` | `80` | порт для `ACCESS_MODE=http` |
| `TELEGRAM_BOT_TOKEN` | — | токен бота |
| `TELEGRAM_CHAT_ID` | — | ID чата |
| `SEED_DEMO_DATA` | `true` | `false` — пустая база |
| `DEMO_USER_PASSWORD`, `DEMO_ACCOUNTANT_PASSWORD` | генерируются | пароли демо-пользователей |
| `IK_PASSPHRASE` | — | пароль архива для `--import` (и для `invoice-keeper export/import`) без вопроса |
| `INSTALL_DIR` | `/opt/invoice-keeper` | папка установки |

Пример установки без единого вопроса:

```bash
mkdir -p /opt/invoice-keeper
cat > /opt/invoice-keeper/.env <<'EOF'
ADMIN_LOGIN=owner
ADMIN_PASSWORD='Надёжный-пароль-1'
APP_TIMEZONE=Europe/Moscow
TELEGRAM_BOT_TOKEN=1234567890:AAH…
TELEGRAM_CHAT_ID=-1001234567890
EOF
chmod 600 /opt/invoice-keeper/.env
bash invoice-keeper-1.6.0.run --yes
```

Для нескольких серверов и повторяемых раскаток удобнее роль Ansible: [`ansible/README.md`](../ansible/README.md).
