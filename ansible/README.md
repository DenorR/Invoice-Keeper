# Invoice Keeper: установка на сервер через Ansible

Простой пошаговый гайд. Выполняйте шаги по порядку и копируйте команды.
Заранее ничего знать не нужно.

Что получится в конце:

- панель по адресу https://ВАШ-IP.sslip.io с настоящим HTTPS-сертификатом;
- напоминания о платежах в Telegram;
- резервная копия базы каждую ночь.

Время: около 15 минут.


## Что понадобится

1. Сервер с Ubuntu 22.04, 24.04 или 26.04.
   Нужны его IP-адрес и пароль root — их присылает хостинг.
2. На сервере открыты порты 80 и 443.
   Это делается в панели хостинга, раздел «Брандмауэр» или «Firewall».
3. Ваш компьютер: Windows 10/11, macOS или Linux.
4. Архив проекта invoice-keeper-1.6.0.zip.
5. По желанию — Telegram-бот. Его можно подключить потом (шаг 8).

Домен покупать не нужно.


## Шаг 1. Установить Ansible на свой компьютер

### Если у вас Windows

1. Нажмите «Пуск», найдите PowerShell, нажмите на него правой кнопкой
   и выберите «Запуск от имени администратора».
2. Выполните команду:

```
wsl --install -d Ubuntu
```

3. Перезагрузите компьютер.
4. Откройте из меню «Пуск» приложение Ubuntu.
   Придумайте имя пользователя и пароль.
   Пароль при вводе не показывается — это нормально.
5. В окне Ubuntu выполните:

```
sudo apt update && sudo apt install -y ansible unzip
```

Дальше все команды вводите в окне Ubuntu.

### Если у вас macOS

Откройте «Терминал» и выполните:

```
brew install ansible
```

Если команда brew не найдена, сначала установите Homebrew с сайта https://brew.sh

### Если у вас Linux (Ubuntu, Debian)

```
sudo apt update && sudo apt install -y ansible unzip
```

### Проверка

```
ansible --version
```

Должна напечататься версия: ansible [core 2.15] или новее.


## Шаг 2. Распаковать проект в домашнюю папку

Windows. Замените ИМЯ на имя пользователя WINDOWS (не Ubuntu!).
Его видно в списке папок — выполните:

```
ls /mnt/c/Users
```

Затем распакуйте (знак ~ в конце обязателен — это папка, куда распаковать):

```
unzip /mnt/c/Users/ИМЯ/Downloads/invoice-keeper-1.6.0.zip -d ~
```

Если архив лежит не в «Загрузках», а, например, на диске D:

```
unzip /mnt/d/invoice-keeper-1.6.0.zip -d ~
```

macOS и Linux:

```
unzip ~/Downloads/invoice-keeper-1.6.0.zip -d ~
```

Перейдите в папку и посмотрите, что в ней:

```
cd ~/invoice-keeper-1.6.0/ansible
ls
```

Должны быть видны: site.yml, inventory.example.yml, roles, group_vars.

ВАЖНО для Windows: работайте именно в папке ~ (домашней папке Ubuntu),
а не в /mnt/c/... или /mnt/d/... Из папок Windows Ansible не читает
свои настройки, и ничего не заработает.


## Шаг 3. Подключиться к серверу по ключу

Ansible заходит на сервер по SSH-ключу. Создайте ключ.
На все вопросы просто нажимайте Enter:

```
ssh-keygen -t ed25519
```

Отправьте ключ на сервер. Вместо 203.0.113.10 впишите IP своего сервера:

```
ssh-copy-id root@203.0.113.10
```

Если спросит yes/no — введите yes.
Потом введите пароль root от хостинга. Это последний раз, дальше пароль не нужен.

Проверка — должно войти на сервер без пароля:

```
ssh root@203.0.113.10
```

Выйти с сервера обратно — командой exit.


## Шаг 4. Скачать модули для Ansible

```
ansible-galaxy collection install -r requirements.yml
```


## Шаг 5. Описать свой сервер

Откройте новый файл:

```
nano inventory.yml
```

Вставьте в него текст ниже.
Вставка в окне терминала — правая кнопка мыши или Ctrl+Shift+V.

```
invoice_keeper:
  hosts:
    my-server:
      ansible_host: 203.0.113.10
      ansible_user: root
      ik_admin_login: owner
      ik_admin_password: "{{ vault_admin_password }}"
      ik_telegram_bot_token: "{{ vault_bot_token }}"
      ik_telegram_chat_id: ""
```

Поменяйте две строки:

- ansible_host — IP вашего сервера;
- ik_admin_login — логин, под которым вы будете входить в панель.
  Только строчные латинские буквы, цифры, точка, дефис или _, от 3 символов.
  Например: owner, admin, ivan.petrov

Отступы (пробелы в начале строк) не меняйте — они важны.

Сохраните файл: Ctrl+O, затем Enter. Выйдите: Ctrl+X.


## Шаг 6. Записать пароль в зашифрованный файл

Пароль администратора и токен бота хранятся в зашифрованном файле.
Даже если кто-то увидит папку, прочитать их не сможет.

Откройте файл:

```
nano group_vars/invoice_keeper/vault.yml
```

Вставьте две строки и впишите свои значения:

```
vault_admin_password: "Придумайте-надёжный-пароль-2026"
vault_bot_token: ""
```

- vault_admin_password — пароль для входа в панель, от 8 символов.
  Нельзя использовать одинарную кавычку '. Знаки $, #, пробелы — можно.
- vault_bot_token — токен Telegram-бота в кавычках.
  Если бота пока нет, оставьте пустые кавычки "".

Сохраните: Ctrl+O, Enter, Ctrl+X.

Зашифруйте файл:

```
ansible-vault encrypt group_vars/invoice_keeper/vault.yml
```

Ansible попросит придумать пароль хранилища (два раза).
ЗАПОМНИТЕ ЕГО — он нужен при каждом запуске.


## Шаг 7. Запустить установку

```
ansible-playbook site.yml --ask-vault-pass
```

Введите пароль хранилища из шага 6.

Первый запуск идёт 3–4 минуты: ставится Docker, собирается приложение,
выпускается сертификат. По экрану бегут строки ok и changed — так и должно быть.

В конце появится итог с адресом панели, примерно такой:

```
  - Invoice Keeper 1.6.0 — https://203.0.113.10.sslip.io
  - 'Swagger: https://203.0.113.10.sslip.io/api/v1/docs'
  - 'Суперадмин: owner (пароль — в Vault)'
  - 'Telegram: не подключён'

PLAY RECAP
my-server : ok=...  changed=...  unreachable=0  failed=0
```

Главное — чтобы было failed=0.

Откройте адрес из итога в браузере и войдите:
логин из шага 5, пароль из шага 6. Готово!


## Шаг 8. Подключить Telegram (можно сделать потом)

1. Создайте бота: в Telegram напишите @BotFather, команда /newbot.
   Он пришлёт токен вида 1234567890:AAH...

2. Запишите токен в зашифрованный файл:

```
EDITOR=nano ansible-vault edit group_vars/invoice_keeper/vault.yml
```

   Впишите токен в строку vault_bot_token: "..."
   и сохраните (Ctrl+O, Enter, Ctrl+X).

3. Запустите установку ещё раз (команда из шага 7). Бот заработает.

4. Создайте группу в Telegram и добавьте туда бота.
   Напишите в группе команду /chatid — бот ответит числом.
   У групп оно с минусом, например -1001234567890.

5. Впишите это число в inventory.yml:

```
nano inventory.yml
```

   Строка должна стать такой (число — ваше):

```
      ik_telegram_chat_id: "-1001234567890"
```

6. Запустите установку ещё раз (шаг 7).
   В итоге будет: Telegram: напоминания в чат -1001234567890

Проверка: в панели добавьте платёж со сроком через 1–2 дня.
В течение минуты в группу придёт напоминание с кнопкой «Оплачено».

ВАЖНО: у каждого сервера должен быть свой бот. Если этот же токен
запущен где-то ещё (например, на вашем компьютере), бот на сервере
перестанет отвечать.


## Если что-то пошло не так

Смотрите последнюю красную строку со словом fatal или FAILED —
в ней написано, что не так. Частые случаи:

Ошибка: UNREACHABLE или Permission denied (publickey)
Решение: неверный IP в inventory.yml или не сделан шаг 3.
         Повторите: ssh-copy-id root@IP

Ошибка: Decryption failed
Решение: неверный пароль хранилища. Введите тот, что придумали на шаге 6.

Ошибка: ik_admin_password: пароль суперадмина обязателен
Решение: забыли --ask-vault-pass в команде, или пароль короче 8 символов.

Ошибка: ik_admin_login: 3–64 символа — строчная латиница
Решение: в логине заглавные или русские буквы. Исправьте в inventory.yml.

Ошибка: 'vault_bot_token' is undefined
Решение: в vault.yml нет строки vault_bot_token. Откройте файл командой
         из шага 8 (пункт 2) и добавьте строку vault_bot_token: ""

Ошибка: Пароли, токен и прокси не должны содержать одинарную кавычку
Решение: уберите символ ' из пароля.

Ошибка: couldn't resolve module/action 'community.docker...'
Решение: не выполнен шаг 4.

Ошибка: долго висит «Панель открывается по https://...», потом падает
Решение: у хостинга закрыты порты 80 и 443. Откройте их и запустите шаг 7 снова.

Ошибка: Ansible is being run in a world writable directory
Решение: вы в папке Windows (/mnt/c/...). Вернитесь к шагу 2.

Бот не отвечает на /chatid
Решение: проверьте токен; убедитесь, что этот бот не запущен где-то ещё;
         запустите шаг 7 снова.

Журнал приложения на сервере (выход — Ctrl+C):

```
ssh root@203.0.113.10 invoice-keeper logs
```


## Что дальше

Обновить до новой версии:
  распакуйте новый архив (шаг 2), скопируйте в новую папку ansible
  свои файлы inventory.yml и group_vars/invoice_keeper/vault.yml,
  запустите шаг 7. Копия базы перед обновлением делается сама.

Сменить пароль администратора:
  EDITOR=nano ansible-vault edit group_vars/invoice_keeper/vault.yml
  затем шаг 7.

Свой домен вместо sslip.io:
  сделайте у регистратора A-запись домена на IP сервера,
  добавьте в inventory.yml строку  ik_domain: pay.example.ru
  (с теми же отступами, что у ik_admin_login), затем шаг 7.

Ещё один сервер:
  допишите его в inventory.yml рядом с первым (со своим ботом) и запустите:
  ansible-playbook site.yml --ask-vault-pass --limit имя-сервера

Полезные команды на сервере:
  invoice-keeper status    — всё ли работает
  invoice-keeper logs      — журнал
  invoice-keeper backup    — сделать резервную копию сейчас
  invoice-keeper backups   — список копий

Настройки меняйте только через inventory.yml и vault.yml с повторным запуском.
Ручные правки файла /opt/invoice-keeper/.env на сервере
следующий запуск перезапишет.
